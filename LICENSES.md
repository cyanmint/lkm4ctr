# License and provenance boundaries

This inventory separates known upstream licenses from files whose AI-generated provenance is known. It does not override any license notice in an individual source file.

## Vendored Linux kernel sources — retain upstream licenses

- `vendor/` contains vendored Linux/Android kernel code. Preserve each file's upstream SPDX and copyright notices, including its GPL variant.

## Existing GPL-licensed project sources — retain their licenses

- `glue/` contains project glue and bridge code with existing GPL SPDX declarations.
- `lkm4ctr_checker/` contains checker sources with existing GPL SPDX declarations.
- Existing GPL declarations elsewhere in the repository also remain unchanged.

## Known AI-generated whole files — Public Domain

- `kernelsu/customize.sh` was generated by AI and has no copyright holder under the project's stated provenance rule. It is identified as Public Domain; this is not a CC0 dedication.
- `module.yaml` and this inventory are AI-generated metadata/documentation and are identified as Public Domain under the same rule; this is not a CC0 dedication.

## Mixed or unverified provenance

Existing files such as the workflow, `README.md`, `kernelsu/module.prop`, and `kernelsu/tests/test_module.py` contain pre-existing material plus AI-assisted edits. They are not relabeled file-wide. Git authorship and source style do not establish whether historical content was AI-generated, so unverified files retain their existing notices or remain unclassified until their provenance is confirmed.
